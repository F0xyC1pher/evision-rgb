# evision-rgb

RGB-подсветка клавиатур на контроллерах **Evision V2** (`320F:5055`) в Linux:
аппаратные эффекты, per-key цвета и совместимость с OpenRGB SDK.

## Обзор

Производители часто используют один и тот же контроллер в разных моделях —
Evision, Wobkey, Ajazz, Kreo и других. Второй интерфейс такого контроллера
предназначен для конфигурации и подсветки, но ядро определяет его как обычную
HID-клавиатуру/мышь. Результат — постоянные USB-ресеты и сбои соседних
устройств на том же хабе.

Проект обходит эту проблему:

- udev-правило отключает второй интерфейс от драйвера `usbhid`;
- утилиты обращаются к нему напрямую через `libhidapi-libusb`.

Основные клавиши и их подсветка при этом работают обычно, через первый
интерфейс.

## Возможности

- чтение состояния: режим, яркость, скорость, цвет;
- 19 аппаратных эффектов подсветки;
- статический цвет, сохранение/восстановление настроек;
- per-key цвета в двух вариантах:
  - **custom** — запись в энергонезависимую память клавиатуры, без фонового процесса;
  - **direct** — потоковая передача для динамических эффектов;
- мост `evision-sdk`: сервер OpenRGB SDK (`127.0.0.1:6742`) для приложений вроде
  [MineLights](https://modrinth.com/mod/minelights).

## Требования

- Linux, Python 3;
- `libhidapi-libusb.so.0` (в Arch — пакет `hidapi`);
- права root нужны только для установки.

## Установка

```sh
sudo ./install.sh
```

Устанавливаются:

| Файл | Назначение |
|---|---|
| `evision-rgb` | CLI-утилита |
| `evision-sdk` | сервер OpenRGB SDK |
| `udev/99-evision-kbd-fix.rules` | отключение второго интерфейса от `usbhid` |
| `udev/kbd-fix-unbind-if1` | вспомогательный скрипт правила |
| `udev/60-evision-rgb.rules` | доступ пользователя к USB (uaccess) |
| `evision-sdk.service` | user-сервис моста OpenRGB SDK |

После установки переподключите клавиатуру или выполните:

```sh
sudo udevadm control --reload-rules
sudo udevadm trigger
```

## Использование

```sh
evision-rgb status                                   # текущее состояние
evision-rgb static ff0000 8                          # статический цвет, яркость 0..9
evision-rgb effect breathing speed=6 color=ff00ff    # эффект
evision-rgb effects                                  # список эффектов
evision-rgb save                                     # сохранить настройки
evision-rgb restore                                  # восстановить настройки
```

### Per-key подсветка

Имена клавиш берутся из keymap самой клавиатуры (команда `0x07`), поэтому
соответствие клавиш и светодиодов не требует вручную подобранных таблиц:

```sh
evision-rgb keys                                     # список клавиш и слотов
evision-rgb custom esc=ff0000 f1=00ff00 1=0000ff     # во flash, без процесса
evision-rgb rainbow                                  # радуга, во flash
```

Команды `custom` и `rainbow` сохраняют результат в памяти клавиатуры — он
сохраняется после завершения команды и после перезагрузки.

Для динамических сценариев (реакция на события игр и т.п.) используется
direct-режим: пока процесс жив, он передаёт полный кадр с заданной частотой.
После завершения клавиатура возвращается к аппаратному режиму.

```sh
evision-rgb key esc=ff0000 f1=00ff00 1=0000ff        # до Ctrl-C
evision-rgb slots 0=ff0000 8=00ff00 9=0000ff 30      # по номерам слотов, 30 с
evision-rgb wave 10                                  # анимированная волна, до Ctrl-C
```

Анимация работает и вместе с Terraria: запусти reader с `--animate`, и фон
будет плавно бегущим градиентом, а эффекты HP/маны/биома — поверх него:

```sh
sudo terraria-rgb --animate
```

### Эффекты

`wave-short`, `wave-long`, `wheel`, `spectrum`, `breathing`, `static`,
`reactive`, `reactive-ripple`, `reactive-line`, `starlight-fast`, `blooming`,
`rainbow-vertical`, `hurricane`, `accumulate`, `starlight-slow`, `visor`,
`surmount`, `rainbow-circle`, `custom`.

## OpenRGB SDK и MineLights

`evision-sdk` поднимает сервер OpenRGB SDK на порту `6742` и представляет
клавиатуру как обычный 128-светодиодный контроллер. Приложения, работающие с
OpenRGB (например MineLights), могут использовать эффекты без родной поддержки
этой модели.

```sh
# настоящий OpenRGB должен быть выключен — порт 6742 должен быть свободен
systemctl --user enable --now evision-sdk
```

Далее в MineLights: **Mods → MineLights → Config → OpenRGB integration → Refresh devices**.

Мост передаёт имена светодиодов (`Esc`, `F1`…`F12`, цифры, буквы, `Num0`…`Num9`),
поэтому эффекты вроде полоски здоровья на F1–F4 или компаса на цифровом блоке
работают без дополнительной настройки. Частота обновления — 10 Гц
(изменяется параметром `--hz`).

Для ручной проверки моста:

```sh
python3 - <<'PY'
import socket, struct, time
s = socket.create_connection(('127.0.0.1', 6742))
def send(pid, data=b''):
    s.sendall(b'ORGB' + struct.pack('<III', 0, pid, len(data)) + data)
send(40, struct.pack('<I', 4))   # версия протокола
send(0)                          # число контроллеров
cols = [0] * 128
cols[0] = 0x0000ff               # Esc — красный
cols[8] = 0x00ff00               # F1 — зелёный
cols[9] = 0xff0000               # 1 — синий
inner = struct.pack('<H', 128) + b''.join(struct.pack('<BBBB', c & 255,
        (c >> 8) & 255, (c >> 16) & 255, 255) for c in cols)
send(1050, struct.pack('<I', 4 + len(inner)) + inner)
time.sleep(2)
PY
```

## Ванильная Terraria

`terraria-rgb` читает здоровье игрока напрямую из памяти ванильной Terraria
(без модов и tModLoader) и шлёт цвет в SDK-мост.

```sh
sudo install -m 755 terraria-rgb /usr/local/bin/terraria-rgb
sudo terraria-rgb                    # --max-hp 125, если макс. HP отличается
```

При запуске скрипт ищет в памяти структуру игрока по байтовому паттерну
(≈3 с), затем раз в 0,2 с читает здоровье и ману:

- `F1`–`F10` — полоска здоровья: зелёная при 100%, красная при 0%;
- цифры `1`–`0` — полоска маны: синяя, яркость зависит от уровня;
- `WASD` — цвет биома: зелёный (лес), жёлтый (пустыня), голубой (снег);
- при смерти (HP = 0) все F-клавиши горят красным.

Адрес пересканируется автоматически после смерти/возрождения игрока.
Работает только пока игра запущена; `Ctrl-C` завершает передачу.

## Нативный OpenRGB

Стоковый OpenRGB не знает PID `320F:5055`. В каталоге `openrgb-patch/` лежит
патч драйвера EVision V2 с картой на 128 светодиодов, снятой с клавиатуры, и
скрипт сборки. Это позволяет использовать обычный OpenRGB вместе с его
плагинами, без SDK-моста:

```sh
cd openrgb-patch
./build.sh
sudo install -m 755 ~/openrgb-custom/openrgb /usr/local/bin/openrgb-evision
openrgb-evision --list-devices
```

Патч использует libusb-путь, поэтому **udev-правило `99-evision-kbd-fix` можно
оставить включённым**: интерфейс 1 остаётся отвязанным от `usbhid`, не создаёт
фейковых клавиатурных событий и не вызывает USB-ресетов. Подробности — в
`openrgb-patch/README.md`.

## Протокол

Пакеты HID по 64 байта, report ID `4`:

```
[0]    report ID (0x04)
[1:3]  контрольная сумма = sum(bytes[3:64]), little endian
[3]    команда
[4]    размер данных
[5:7]  смещение, little endian
[7]    статус в ответе (0 — успех)
[8:]   данные
```

Основные команды: `0x01` / `0x02` — начало и конец конфигурации,
`0x03` — возможности, `0x05` / `0x06` — чтение и запись конфигурации,
`0x0B` — запись пользовательских цветов, `0x12` / `0x13` — динамические цвета.

Описание протокола получено из реверс-инжиниринга драйвера EVision V2
в проекте OpenRGB (GPL-2.0).

## Диагностика

Проверить, что второй интерфейс не захвачен драйвером `usbhid`
(при работающем мосте он может быть занят `libusb` — это нормально):

```sh
readlink -f /sys/bus/usb/devices/*:1.1/driver
```

Логи моста:

```sh
journalctl --user -u evision-sdk -f
```

## Ограничения

- Некоторые ревизии прошивки не отвечают на команды второго интерфейса —
  утилита сообщит `no response`.
- Direct-режим требует работающего процесса и не сохраняет результат после
  выхода; для постоянных расцветок используйте `custom`.
- Запись пользовательских цветов (`custom`, `rainbow`) использует ресурсы
  энергонезависимой памяти клавиатуры — не вызывайте её слишком часто.
